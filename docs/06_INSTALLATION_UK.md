# Інтеграція та тестове встановлення

Цей пакет містить source-прототип, не готовий Workshop addon. `.gproj`, скомпільовані ресурси та Workshop GUID не вигадані: у вихідних архівах немає достатніх даних для коректного manifest залежностей. Створення, компіляція й упаковка виконуються Workbench цільової збірки.

## Потрібні матеріали

- Arma Reforger/Workbench цільової 1.9 збірки; dedicated server і щонайменше два клієнти для тесту.
- Повний встановлений EGC addon, який уже визначає EGC_StaffConfig, EGC_StaffList, EGC_BanSystem, EGC_VIPConfig і розширення GameMode.EGC_IsPlayerVIP. Не дублювати їх у новому addon.
- Справжні GUID/версії залежностей чинного EGC. Особливо addon, що визначає ServerAdminTools_PauseMenuButtonComponent, та ACE Trenches, якщо повний EGC підключає відповідні скрипти. Відсутність цих визначень не виправляється новою адмінкою.
- Налаштований backend сервера для UID та BanService, чинні EGC_Staff.json/EGC_Vips.json, резервна копія server profile.
- Рішення власника щодо startup-loop EGC з документа 04. Не створювати або змінювати security.bin новим модом.

CasualAdminTools/WIU_AdminTools новому коду не потрібні. Якщо **оригінальний EGC** окремо залежить від іншої адмінки, ця вихідна залежність залишається до погодженої міграції EGC. Не видавати повний EGC-набір за незалежний від такого addon.

## Workbench

1. На тестовій копії створити новий addon `EGC Admin Tools`, додати залежності базової гри та справжнього EGC addon через Workbench. Не переписувати project GUID чинного EGC.
2. Скопіювати **вміст mod/** в корінь нового addon. Не копіювати research/, оригінальні EGC-скрипти або `.c.bk`.
3. Перевірити в resource browser новий `Configs/System/chimeraInputCommon.conf`, його merge із IngameContext і action `EGC_AT_ConsoleToggle`. Конфіг створено за стандартною схемою ActionManager, але завантаження конкретним Workbench ще не виконано. При необхідності пересеріалізувати його через редактор, зберігши власну action, F8 та ActionRefs; не підключати CGG_AdminToggle.
4. Запустити компіляцію scripts/resources. Зберегти повну діагностику; не ігнорувати missing type/method/resource. Шрифт із базової гри звірено зі snapshot: `{3E7733BAC8C831F6}UI/Fonts/RobotoCondensed/RobotoCondensed_Regular.fnt`; ресурс усе одно потрібно перевірити в установленій збірці.
5. Якщо компіляція пройшла, створити локальну тестову збірку addon стандартними засобами Workbench. Тільки після runtime-тестів пакувати публічну версію. Цей source ZIP не замінює game package.

## Тестовий сервер і клієнти

1. Зробити окрему копію mission/server config/profile. Підключити новий addon разом із його реальними залежностями через звичайний список mods; використати фактичний ID створеного addon, не placeholder GUID із документації.
2. Не змінювати формати EGC_Staff.json, EGC_Vips.json, EGC_Bans.json. Staff map: `staff: { UID: опис }`; VIP map: `vips: { UID: опис }`. Файли й UID повинні відповідати наявному процесу EGC.
3. Для тестового адміністратора: справжній backend UID у чинному staff; активний ADMINISTRATOR або SESSION_ADMINISTRATOR через чинний login; він не має бути VIP. Нова адмінка не видає ролі автоматично і не містить login password.
4. Сервер і клієнти повинні мати однакову збірку нового addon. Після входу натиснути F8. Звичайний користувач може відкрити порожню оболонку, але сервер має відмовити в даних і командах. Клієнтське приховування кнопки не є захистом.
5. Обрати рядок гравця; перевірити ім'я цілі зверху, UID і статус у досьє. На refresh попередній вибір скидається. Для Kick потрібна причина й повторне локальне підтвердження. Сервер не покладається на підтвердження для перевірки прав.
6. Бан-експорт — лише читання існуючого EGC snapshot. Після відкриття експорту кнопки Назад/Далі перегортають його сторінки; Оновити повертає список гравців. Показано не більше перших 100 банів з оригінального exporter, можливе запізнення понад 5 хвилин при backend-помилках.
7. Журнал шукається за `[EGC_AT_AUDIT]` у серверному console.log; часовий пояс — локальна конфігурація сервера, не гарантовано UTC. Окремого writer в EGC-файли журналів немає. Забезпечити звичайну ротацію логів на хостингу.
8. Виконати всю матрицю з 05_IMPLEMENTATION_AND_TESTS_UK.md на dedicated та listen. Залишити source-прототип на тестовому сервері до отримання доказів компіляції та мережевої роботи.

## Відкат

Прибрати тільки новий addon із тестового списку mods та перезапустити сервер/клієнти. Новий мод не записує ban/VIP/staff-файли, тож міграції цих реєстрів немає. Kick/Heal — уже виконані gameplay дії; вимкнення addon не відновлює їхній попередній стан. Оригінали EGC та ZIP не редагувалися.

## Відтворення статичних перевірок

З кореня workspace:

```
python EGC_AdminTools/tools/audit_archives.py
python EGC_AdminTools/tools/verify_static.py
```

Перший скрипт використовує оригінальні ZIP під `/tmp/codex-remote-attachments`, другий — розпакований research/ із цього workspace. У source-пакеті сторонні оригінали не поширюються; для запуску в іншому місці потрібно зберегти такі самі каталоги або явно змінити шляхи локального стенда. Скрипти не є компілятором Enfusion.
